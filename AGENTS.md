# Proyecto de finanzas personales

- Trabajar en una rama de entrega o funcionalidad. No hacer push directo a `main`.
- Antes de **cada commit y cada push**, ejecutar desde la raíz, en este orden:
  1. `dart format .`
  2. `flutter analyze`
  3. `flutter test`
- Si falla algún comando, corregir y volver a ejecutar los tres antes de continuar.
- Conservar la estructura y los cambios de otros integrantes.
- Usar Flutter sencillo: pantallas separadas, widgets reutilizables, `setState`,
  Provider, navegación y alertas. Evitar arquitecturas o generación de código complejas.
- Entrega 1: interfaz y navegación, datos de ejemplo. No simular que existe
  autenticación, SQLite, importación bancaria o notificaciones reales.
- No atribuir conclusiones personales a integrantes sin que las proporcionen.
